## EasyPost {#easypost-technology-strategy}

**Technology strategy and engineering leadership · 2019–present**

I joined EasyPost as an engineer building warehouse logistics, inventory, order integrations, and fulfillment software. My scope expanded through engineering management and platform leadership to company-wide technology strategy.

As platform leadership broadened, I was responsible for infrastructure, finance systems, shared services, and developer tooling. That included redesigning financial data pipelines to shorten revenue-recognition time, decomposing a monolithic application into services, and improving reliability and developer throughput.

I became Vice President of Engineering in 2025, leading a 130+ engineer organization across Core API, Enterprise, Platform, and international subsidiaries. In 2026 I became Chief Technology Officer, with responsibility across product, platform, data, and infrastructure. The work now centers on simplifying overlapping products and systems and evaluating technology investments against cost, margin, reliability, and risk.

[EasyPost leadership biography](https://www.easypost.com/about/)

## Engine Yard {#engine-yard}

**Cloud API architecture and development**

I architected and led development of the Engine Yard API, from backend services to the interfaces developers used to operate applications and infrastructure.

The official Ruby client and command-line utility, `ey-core`, support application deployment and environment management, including a mocked mode for testing integrations without live API calls.

[Engine Yard Core API client](https://github.com/engineyard/core-client-rb)

## Fastly {#fastly}

**Backend systems, data infrastructure, and reliability · 2016–2019**

My work moved from customer-facing APIs toward the systems used to operate the platform. I worked on backend APIs and web application firewall development, then internal data pipelines and site-reliability tooling, and finally infrastructure development in site reliability engineering.

The implementation work crossed Ruby, Go, Varnish, NSQ, Kubernetes, Chef, and Terraform. The more durable thread was the progression from product-facing software into the infrastructure and operational systems beneath it.

## Speaking {#sapporo-rubykaigi-2012}

**Release Early and Release Often: Reducing deployment friction**

Sapporo RubyKaigi · Sapporo, Japan · September 14, 2012 · Engine Yard

I presented Engine Yard’s approach to automated testing, continuous integration, and deployment. The main cloud codebase could be released at least daily while retaining a rigorous testing and release process.

[Conference program and abstract](https://sapporo.rubykaigi.org/2012/en/schedule/details/37.html) · [Event report (Japanese)](https://gihyo.jp/news/report/01/sapporo-rubykaigi2012/0001)
